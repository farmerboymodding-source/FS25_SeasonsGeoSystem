# FS25_SeasonsGeoSystem
Seasons Geo System FS19-like for Farming Simulator 25
A framework to introduce custom climate management, crop phenology, and advanced fog into **Farming Simulator 25**, reviving and evolving the beloved *Seasons GEO* concept from FS17/FS19.

This system allows modders to completely redefine the agronomic and meteorological rules of any macro-region in the world, bypassing the limits imposed by the Giants Software game engine through dynamic runtime injection via Lua scripts.

---

## 🚀 Key Features

* **Clean Modular Architecture:** The source code is strictly separated into logical modules (`Main`, `Crops`, `Weather`, `Fog`), ensuring maximum readability, ease of debugging, and zero performance impact (no micro-stuttering in the game's update loop).
* **Dynamic Weather Injection (Weather Hacking):** Solves the native base game limitation. If a map does not provide a certain weather type in a season (e.g., rain in winter or snow in summer), the code clones a physics model (particles, wind, clouds) from other seasons at runtime, giving the modder total control over the climate.
* **Synchronized RNG Pool Hacking:** The system dynamically modifies the internal `weightedVariations` tables of the game engine. This ensures that only the weather variations defined by the user in the XML are drawn, zeroing out the probability of foreign weather types without destroying the native physics pointers.
* **Smart Crop Management:** Instead of blindly iterating or using fixed arrays, the system dynamically scans all registered fruits (`g_fruitTypeManager`), applying custom planting/harvesting windows and growth skips (`<update>`) only for the crops explicitly configured in the GEO XML.
* **Native Double Cropping Support:** Allows for the simulation of real-world intensive agricultural rhythms (such as in the Po Valley or Southern USA), enabling accelerated catch-up growth for short-cycle crops planted in summer (e.g., second-crop soybeans after wheat).
* **Multiplayer Ready (EXPERIMENTAL):** Total synchronization of weather packets between the Dedicated Server and Clients. The code SHOULD BE protected against visual and logical desyncs and safely handles forecast rebuild events (`isRebuild`) without generating pointer errors or log crashes.
  *NOTE that I didn't try the mod in multiplayer myself, it SHOULD work.
* **Volumetric Fog Control:** Advanced management of fog banks (`groundFog` and `heightFog`), linking density, extra height, and appearance/dissipation times to specific weather states.

## 📂 Project Structure

The logical core of the mod is divided into the following LUA source files:

1. **`SeasonGeoMain.lua`:** The entry point of the mod. Handles initialization, map event listening, submodule loading, and parameter reload console commands (`seasonGEO_reload`).
2. **`SeasonGeoCrops.lua`:** Handles the mapping of growth states (1:1 or advanced) and overwrites the phenological periods of planting and harvesting.
3. **`SeasonGeoWeather.lua`:** Manages climate compilation and hooks into the native `Weather.fillWeatherForecast` function to generate weather forecasts.
4. **`SeasonGeoFog.lua`:** Manages the environmental parameters related to ground fog, valley depth, and low cloud visual clipping.

## 🛠️ Automated Generation Tools

The real revolution of this framework lies in the standardization of environmental development through two files included in the project:

### 📄 1. `SeasonGeo_MasterPrompt.md`
This is the **Golden Rules Manifesto** of the GEO system. This file acts as a structured *System Prompt* for Large Language Models (like Qwen Code, ChatGPT, etc.). It definitively explains to the AI how to interpret the agronomic phenology of a real country and how to translate it into a rigorous, hallucination-free JSON output, respecting the physical limits of daylight duration and meteorological balancing (the sum of seasonal probabilities must always equal 100).

### ⚙️ 2. `seasonGeoStandard.xml`
This represents the **Fundamental Blueprint**. It is the standardized XML file containing the exact syntax accepted by the Lua engine. It includes the reference mapping of all primary crops (Wheat, Barley, Maize, Soybeans, Canola, Sugarbeets, Potatoes, etc.) and acts as an empty structural template. Any new geographical file (e.g., *Northern Italy*, *Sicily*, *Midwest USA*) is generated by cloning and expanding this technical pillar, ensuring the absolute absence of syntax errors or forgotten tags.

## ⚙️ Configuration & Installation

To register a new regional climate configuration within the mod, simply declare the presence of the XML file in the `modDesc.xml` of your GEO archive using the designated syntax:


<modDesc>
    ...
    <SeasonGeoSystem>
        <isReady value="true" />
        <xmlFilename path="seasonGeoNorthernItaly.xml" />
    </SeasonGeoSystem>
</modDesc>

The main Lua module will automatically detect the active GEO mod, extract the path of the configured XML file, and execute the runtime optimization during map loading.
